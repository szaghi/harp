# HARP — Claude Code project notes

HARP (Horizon-Aware Recommender and Planner) is a CLI tool that selects
deep-sky targets for an astrophotography night session from: date, site
location, telescope+camera rig, the site's free-horizon profile, and Moon
status.

## Layout

- `src/harp/` — package sources (src layout; import only works installed):
  `horizon.py` (.hrz mask + builder), `catalog.py` (pyongc + curated
  rescue + target classification), `sharpless.py` (Sh2 H II regions +
  Sh2<->NGC/IC/M size-override concordance, vendored SQLite/JSON in
  `data/`; rebuilt by `tools/build_*.py`), `solar_system.py` (Moon +
  planets as moving targets, offline; satellites gated behind an online
  kernel),
  `optics.py` (rig FOV/mosaic), `ephemeris.py` (darkness window,
  alt-az, Moon, Solar System alt-az + apparent size), `planner.py`
  (orchestration -> NightPlan; splits fixed vs moving bodies), `report.py`
  (table/CSV/charts), `config.py` (CLI > config > defaults layering),
  `mosaic.py` (per-panel sky geometry), `nina.py` (N.I.N.A. CSV exports —
  header choice works around NINA's dec-import bug, see module docstring),
  `exposure.py` (sub length + ISO for camera-on-tracker: NPF trailing
  limit, sky-saturation limit, frames/storage for a requested
  integration), `cli.py` (Typer: plan/mosaic/list/horizon)
- `examples/` — working sites.yaml, balcony.hrz, horizon points file,
  sample outputs; tests assert against these (do not regenerate blindly)
- `android/` — experimental Android frontend (Kotlin/Compose + Chaquopy);
  embeds `../../src` as its Python source set — the app and CLI share the
  core, `harp.api` is the stable surface between them. Built by CI
  (android.yml, debug APK artifact); see android/README.md for the
  device checklist. Never break `harp.api` without bumping API_VERSION.
  Tabs: Home (a solar-system dashboard — planets are tab shortcuts, and
  their `tabIndex` must track `MainActivity`'s list or a planet silently
  opens the wrong tab), Horizon, Plan, Align, Shoot, Settings. The Shoot
  tab is a manual astro camera + intervalometer: `CameraCapabilities`
  (hardware probe + exposure calibration), `CaptureController` (CameraX
  binding, verified DNG capture), `SequenceService` (foreground service
  for unattended runs), `StopLadder`/`StopWheel` (detented arc control),
  `ShootScreen`/`ShootViewModel`, and `shoot_bridge.py` (JSON in/out over
  `harp.exposure`, mirroring `planner_bridge.run_plan`).
- `tests/` — pytest suite, shared fixtures in `conftest.py`
- `docs/` — VitePress site (GitHub Pages via CI); `docs/guide/changelog.md`
  is generated by `release.sh`, do not hand-edit
- `licensing/` — quad license texts (GPL3 / BSD-2 / BSD-3 / MIT)

## Commands

- `make dev` / `test` / `lint` / `fmt` / `clean` — the only supported dev
  interface; always via `.venv`, never system Python
- `./release.sh --major|--minor|--patch|X.Y.Z` — trunk release on `main`,
  tag push triggers CI → PyPI (never publish locally)
- `gradle -p android :app:assembleDebug --rerun-tasks` — build the Android
  debug APK **locally**. There is no Gradle wrapper, so this uses the system
  `gradle`. Output: `android/app/build/outputs/apk/debug/app-debug.apk`.
  Toolchain: Gradle 8.13, JDK 21, SDK at `/home/stefano/android-sdk`
  (only `android-35` installed). **Run this before claiming any Kotlin change
  works** — GitHub Actions is not the only gate, and a local build is far
  cheaper than a push/CI round-trip.

## Conventions

- Version: `pyproject.toml` is canonical, `src/harp/__init__.py` mirrors it
  (kept in sync by `release.sh` — bump both or neither)
- Exceptions: raise subclasses of `harp.errors.HarpError`, never bare
  `Exception`
- Android toolchain is pinned low: **compileSdk/targetSdk 35, AGP 8.7.3**.
  Library versions must respect that floor — CameraX is held at **1.5.x**
  because 1.6.x demands compileSdk 36 + AGP 8.9.1 and fails
  `:app:checkDebugAarMetadata` outright. Checking that an API exists in a
  release is *not* enough; check the release's AGP/compileSdk requirement too.
- Editing `src/` requires `--rerun-tasks` on the next Android build, or the
  APK silently ships stale bytecode — see `android/README.md` for the why
- Chaquopy cannot pass Python kwargs from a Kotlin map, so every bridge
  under `android/app/src/main/python/` takes one JSON string and returns
  one. Return failures **in-band** (`{"error": "..."}`) rather than
  raising: an exception crossing JNI arrives as a bare `PyException` with
  no message, which tells the user nothing at a dark site. Kotlin must
  then check for the `error` key — a successful call is not a success.
- Camera2 reports **continuous ranges**, never stop lists
  (`SENSOR_INFO_EXPOSURE_TIME_RANGE`, `SENSOR_INFO_SENSITIVITY_RANGE`).
  Any "real stops" the UI offers are HARP's own ladder clamped to the
  device (`StopLadder`). Values past the advertised ceiling exist only
  when `ExposureCalibration` measured them, and must be marked as such —
  rendering them as ordinary stops claims a guarantee the sensor never
  gave.
- The neutrality rule reaches the UI: `harp.sky`/`harp.exposure` return
  `None` rather than guessing, so a site with no Bortle/SQM yields an
  exposure but a null ISO. Render the gap and name the fix; never
  substitute a plausible default.
- Global Python conventions (ruff patterns, typing, docstrings, logging)
  come from `~/.claude/CLAUDE.md` — NumPy-style docstrings here (scientific
  code)
